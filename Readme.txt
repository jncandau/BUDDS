1. PURPOSE
----------

Run forward HYSPLIT trajectories from the areas defoliated by the spruce
budworm, for the years 2014 to 2019:

  - Start points : centre of every 5-km grid cell containing defoliation in the
                   year of the simulation (all severity classes), weighted by
                   its defoliated area in km2 ("any + weight" rule, section 6.1)
  - Heights      : 100, 200, 300, 500, 750 and 1000 m above ground level (AGL)
  - Dates        : every day from June 21 to August 21 (62 days)
  - Start times  : every 30 min from 16:00 to 21:00 EDT (11 start times per day)
                   = 20:00 to 01:00 UTC (HYSPLIT works in UTC; EDT = UTC - 4 h)
  - Duration     : 15 h, forward
  - Meteorology  : NAM 12 km (ARL "nams" archive), daily files
                   YYYYMMDD_hysplit.t00z.namsa

5. HOW TO USE IT
----------------

All jobs run on Fir. Scripts are in ~/projects/def-cbataill/jcandau/BUDDS;
data and results go to ${SCRATCH} (/scratch/jcandau).

  cd ~/projects/def-cbataill/jcandau/BUDDS

E-mail notifications: the batch scripts contain the placeholder
"#SBATCH --mail-user=YOUR_EMAIL@example.com" (to keep personal addresses out of
the repository). Give your address on the command line, which overrides it:

  sbatch --mail-user=<your address> <batch script>

or replace the placeholder in your local copy (do not commit it).

Step 1 - Start points (one job, all years)

  sbatch Hysplit_start_points_batch_script.sh

  Runs Create_point_coverage_for_Hysplit_runs.R from ${SCRATCH} (1 h and 16 GB
  requested; the 1-km version took 28.5 min and 5.3 GB).
  Output in ${SCRATCH}/output/hysplit_start_points/ (see section 6.1). It
  overwrites the files of a previous run (rename the folder first to keep them).
  Check summary.csv for the number of points and the defoliated area per year.

Step 2 - Meteorology (on a LOGIN node, one or more years)

  nohup bash Extract_NAMS.sh 2014 > ${SCRATCH}/NAMS/extract_2014.log 2>&1 &

  Nearline is NOT mounted on the compute nodes, so this cannot be a SLURM job
  (the first attempt, job 5462234, failed with "tar file does not exist").
  nohup keeps it running after you log out; note the login node (hostname) to
  find the process again with ps. Several years: Extract_NAMS.sh 2015 2016 ...

  For each year, extracts June 21 to August 23 (64 daily files, about 80 GB)
  from <YEAR>.tar to ${SCRATCH}/NAMS/<YEAR>/ and checks that no file is
  missing (the log lists the MISSING files and the script exits with an error
  otherwise). The last line of the log is
  "<YEAR>: <n> files in ..., <m> missing, finished <date>".
  The tar file must first be recalled from tape, which can take a while
  (check with: lfs hsm_state <tar file>; "released" = still on tape only).

Step 2b - Exclude the start points outside the NAM grid (login node, seconds)

  Rscript Flag_NAM_domain.R            # all years 2014-2019 (or: ... 2014 2015)

  HYSPLIT accepts a start point only if its grid cell satisfies
  2 <= INT(x) < NX-2 and 2 <= INT(y) < NY-2 (library/hysplit/metpos.f);
  otherwise the WHOLE run stops with "start point not within (x,y,t) any data
  file" (first 2014 test, job 5478026: all 66 runs of batch b0001 failed).
  The script reads the grid from the NAM file header (Lambert conformal,
  461 x 401 points, 12 km), computes the grid position of each point (same
  conversion as HYSPLIT, checked to 1e-4 cell), excludes the points outside
  the usable grid (margin 0.05 cell), and checks with a 1-hour HYSPLIT run
  that all the remaining points are accepted. It adds in_nam_domain to
  hysplit_points_<YEAR>.csv, rewrites the start files with the in-grid points
  only (point_id unchanged), and writes points_off_NAM_grid_<YEAR>.csv and
  nam_domain_summary.csv. It can be rerun. 0_Start_hysplit_array.sh refuses
  to run before it.

    Year  Points off grid   Area excluded      Where
    2014  148 of 3,376      558 km2 (1.28%)    Yukon, northern BC, NWT (> 61.9 N)
    2015  290 of 5,006    1,556 km2 (2.35%)    Yukon, northern BC, NWT (> 62.9 N)
    2016-2019       0              0

Step 3 - HYSPLIT runs (one array per year, or per year and height)

  ./0_Start_hysplit_array.sh 2014          # all 6 heights in each task
  ./0_Start_hysplit_array.sh 2014 500      # only 500 m

  This checks the inputs, counts the points and writes
  Hysplit_batch_script_2014.sh (or Hysplit_batch_script_2014_0500m.sh) but does
  NOT submit it. Check the script, then:

  sbatch Hysplit_batch_script_2014.sh

  - 62 array tasks per year, one per day (task 1 = June 21, task 62 = August 21).
    Each task runs the 11 start times of its day.
  - Each task runs, for each start time, all batches of up to 1000 points (and
    every height, or the requested one). Wall time = number of runs x 10 s +
    15 min, computed from the number of points. Memory 4 GB.
  - All work is done on node-local disk (${SLURM_TMPDIR}): the CONTROL files
    are written there, the 3 met files of the day are copied there, and the
    tdump files are packed into ONE tar.gz per day on scratch. This keeps the
    number of files on /scratch low (see section 7).
  - Each task then converts its day to GeoParquet (section 6.4), about 1-2 min.
  - A failed or interrupted array can simply be resubmitted: the HYSPLIT runs
    are skipped when the day's tar.gz exists, and the conversion when the day's
    GeoParquet files exist (positions and trajectories, one per height).
  - Logs: ${SCRATCH}/hysplit_logs/<YEAR>/HYS_<YEAR>_<jobid>_<task>.out

Make_hysplit_CONTROL_files.sh on its own (e.g. to inspect CONTROL files):

  bash Make_hysplit_CONTROL_files.sh 2014         # all heights
  bash Make_hysplit_CONTROL_files.sh 2014 500     # one height

  Writes ${SCRATCH}/hysplit_control/<YEAR>/<H>m/CONTROL_<YYYYMMDD>_<HHMM>UTC_<H>m_b<NNNN>
  and control_list_<YEAR>.txt (682 start times x heights x batches, e.g. about
  29,000 files for 2019 at 5 km).
  Environment variables can override its settings: POINTS_PER_RUN, POINTS_DIR,
  MET_ROOT, CONTROL_ROOT, TDUMP_ROOT, and START_INDEX (start time k or k1-k2,
  1-682).

  Start time number k (1-682):
    day (k - 1) / 11 after June 21, time 16:00 + 30 min x ((k - 1) mod 11) EDT
    e.g. 1 = June 21 16:00 EDT, 11 = June 21 21:00 EDT, 12 = June 22 16:00 EDT,
         682 = August 21 21:00 EDT. Array task d runs k = 11 (d - 1) + 1 to 11 d.


6. OUTPUTS
----------

6.1 Start points: ${SCRATCH}/output/hysplit_start_points/

  How they are built ("any + weight" rule):
    1. The polygons are rasterized on a 1-km grid (EPSG:3978): a 1-km cell is
       defoliated if its centre falls in a defoliated polygon; when polygons
       overlap, the highest severity is kept.
    2. The 1-km grid is aggregated to a 5-km grid (both snapped to multiples of
       5 km, identical for all years). Every 5-km cell with at least one
       defoliated 1-km cell is a start point, located at the centre of the 5-km
       cell, with weight_km2 = number of defoliated 1-km cells (1 to 25).
       The total defoliated area is conserved (checked for 2014: 43,620 km2 at
       1 km = sum of the 5-km weights).

  severity_1km_<YEAR>.tif        1-km severity raster (codes below, 255 = not
                                 defoliated)
  points_5km_<YEAR>.tif          5-km rasters: weight_km2, severity_max,
                                 severity_mean
  hysplit_points_<YEAR>.csv      one row per point and height:
                                   point_id, lat, lon, height_m,
                                   weight_km2      defoliated km2 in the 5-km cell
                                   km2_light, km2_moderate, km2_mod_to_severe,
                                   km2_severe      the same, by severity class
                                   severity_max, severity_label (of the max),
                                   severity_mean   area-weighted mean code
                                   x_3978, y_3978  cell centre in EPSG:3978 (m)
  hysplit_starts_<YEAR>_<H>m.txt one file per height (H zero-padded: 0100m,
                                 0200m, 0300m, 0500m, 0750m, 1000m), lines
                                 "lat lon height". Line i is the i-th point_id of
                                 the year in every height file.
  summary.csv                    points, starts and defoliated km2 (total and by
                                 class) per year

  Severity codes: 1 = Light, 2 = Moderate, 3 = Moderate-to-Severe, 4 = Severe.

6.2 CONTROL files (written by Make_hysplit_CONTROL_files.sh)

  One per start time x height x batch of up to 1000 points. Example
  (CONTROL_20140621_2000UTC_0100m_b0001):

    14 06 21 20 00                 start time (UTC): YY MM DD HH MM
    1000                           number of starting locations
    48.0001 -67.0001 100           lat lon height (m AGL), x 1000
    ...
    15                             run time (h)
    0                              vertical motion: from the met data
    15500                          top of model (m AGL)
    2                              number of met files
    ${SCRATCH}/NAMS/2014/
    20140621_hysplit.t00z.namsa    met file of the UTC start day
    ${SCRATCH}/NAMS/2014/
    20140622_hysplit.t00z.namsa    met file of the following day
    <tdump directory>/
    tdump_20140621_2000UTC_0100m_b0001

  Batch b<NNNN> holds lines (NNNN-1) x 1000 + 1 to NNNN x 1000 of the height
  file, i.e. the same point_id range in hysplit_points_<YEAR>.csv. Trajectory
  number i in a tdump file is point (NNNN-1) x 1000 + i of the year.

6.3 Trajectories: ${SCRATCH}/hysplit_tdump/<YEAR>/

  tdump_<YEAR>_<YYYYMMDD>[_<H>m].tar.gz   one per day (array task), containing
      <H>m/tdump_<YYYYMMDD_HHMM>UTC_<H>m_b<NNNN>   one tdump per start time,
                                                   height and batch
      run_log_<YEAR>_<YYYYMMDD>.txt                runs completed/failed, and
                                                   runs where HYSPLIT dropped points
  YYYYMMDD in the tar.gz name is the local (EDT) date; the tdump names use UTC
  (the starts at 00:00-01:00 UTC are on the next UTC day).
  *_FAILED.tar.gz: at least one run failed (see the run log); the task exits
  with an error and is rerun if the array is resubmitted.

  tdump positions are written every hour (16 positions per trajectory, 0-15 h).

6.4 GeoParquet: ${SCRATCH}/hysplit_parquet/  (for selections and spatial analysis)

  Written by Convert_tdump_to_GeoParquet.R at the end of each array task.
  GeoParquet 1.1, WKB geometry in lon/lat WGS84, zstd compression, row groups
  of 100,000 rows, rows sorted along a Z-order curve of their location (so
  spatial filters skip most row groups). One file per day and height, in
  Hive-style folders read as one table by DuckDB, arrow or geopandas:

  positions/year=<YYYY>/date=<YYYYMMDD>/height=<HHHH>/part-0.parquet
      one row per trajectory and hour, POINT geometry:
      point_id, start_time_utc, height_m, age_h, time_utc, lat, lon,
      alt_agl_m, pressure_hpa, geometry

  trajectories/year=<YYYY>/date=<YYYYMMDD>/height=<HHHH>/part-0.parquet
      one row per trajectory, LINESTRING geometry and bbox struct
      (xmin, ymin, xmax, ymax; declared as the GeoParquet "covering"):
      point_id, start_time_utc, height_m, n_positions, duration_h, complete,
      start_lat, start_lon, end_lat, end_lon, end_alt_agl_m, max_alt_agl_m,
      weight_km2, km2_light, km2_moderate, km2_mod_to_severe, km2_severe,
      severity_max, severity_label, severity_mean, bbox, geometry

  - A trajectory is identified by (point_id, start_time_utc, height_m).
  - date = local (EDT) date of the array task; all times are UTC.
  - complete = FALSE when the trajectory stopped before 15 h (left the met grid).
  - Trajectory -> start point: from the batch number, checked against the start
    coordinates in the tdump header; if HYSPLIT dropped points (renumbered
    trajectories), matched to the nearest start point instead.
  - weight_km2 and the severity columns come from hysplit_points_<YEAR>.csv:
    weight the trajectories by weight_km2 to account for the defoliated area.
  - Size: about 0.4 KB per trajectory (positions + trajectories), i.e. about
    50 GB for the whole 2014-2019 set at 5 km.

  Convert one day by hand:
    Rscript Convert_tdump_to_GeoParquet.R \
        ${SCRATCH}/hysplit_tdump/2014/tdump_2014_20140621.tar.gz \
        ${SCRATCH}/output/hysplit_start_points/hysplit_points_2014.csv \
        ${SCRATCH}/hysplit_parquet

6.5 Querying the GeoParquet files with DuckDB

  DuckDB 2.0.1 (command-line program) is installed in ~/software/duckdb-2.0.1
  (official Linux build from GitHub, checksum verified), linked as ~/bin/duckdb.
  The spatial extension is in ~/.duckdb/extensions/v2.0.1/ (shared home, so it
  also loads on compute nodes, which have no internet access).
  ~/.duckdbrc runs at the start of every session:
      LOAD spatial;
      SET geometry_always_xy = true;

  Example_queries.sql defines two views on ${SCRATCH}/hysplit_parquet,
  "traj" (one row per trajectory) and "pos" (one row per trajectory and hour),
  and gives examples of: counts per partition, time filters, trajectories
  crossing a polygon weighted by weight_km2, positions within a polygon,
  weighted density grid of end points, join of the two views, distance on the
  ellipsoid, and export to GeoPackage for QGIS or R/sf.

    duckdb < Example_queries.sql                  # run all the examples
    duckdb                                        # interactive, then:
      .read Example_queries.sql
      SELECT ... FROM traj WHERE ...;

  Notes:
  - SET geometry_always_xy = true is required in DuckDB 2.0 for spheroid
    measures (ST_Length_Spheroid, ST_Distance_Spheroid) and GDAL exports, which
    otherwise stop with an error; it tells DuckDB that coordinates are
    (longitude, latitude). It becomes the default in DuckDB 2.1.
  - year, date and height come from the folder names; the views read them as
    INTEGER, VARCHAR ('YYYYMMDD', local EDT date) and INTEGER (m AGL) with
    hive_types (without it, height is read as the text '0100').
  - ST_Intersects/ST_Within work on lon/lat as planar coordinates (polygon
    edges are straight lines in lon/lat), like sf with s2 turned off.
  - Tested on the 2023 test day: DuckDB reads the geometry as
    GEOMETRY('OGC:CRS84'); the polygon intersection gives the same counts and
    weighted sums as R/sf; the GeoPackage export is read by GDAL with the
    correct lon/lat order; all the examples run in under 1 s.


7. SIZES, LIMITS AND CAVEATS
----------------------------

  - Number of simulations: 682 start times per year. For one point at one height
    over 2014-2019: 682 x 6 heights x 6 years = 24,552 trajectories. The total
    is 24,552 x the number of points (counting each point in each year it is
    defoliated).
  - Effect of the grid resolution (start points 2014-2019, computed from the
    1-km rasters of the first run):

      Grid / rule               Points  Trajectories   Reduction  CPU-h (est.)
      1 km                     436,957  1.79 billion          -        2,500
      5 km, any + weight        31,206   128 million        14x       120-200
      5 km, centre only         17,452    71 million        25x
      10 km, any + weight        9,664    40 million        45x
      10 km, centre only         4,384    18 million       100x

    5 km "any + weight" was chosen: the NAM grid is 12 km, so trajectories
    starting 1 km apart are nearly identical; the "centre only" rule would drop
    44% of the 5-km cells containing defoliation (small patches and outbreak
    edges); the weight keeps the total defoliated area.
  - Expected at 5 km (exact numbers in summary.csv after step 1):

      Year  Points  Runs/task (day)  Wall time requested
      2014  ~3,380        264              0:59
      2015  ~5,000        396              1:21
      2016  ~5,180        396              1:21
      2017  ~5,270        396              1:21
      2018  ~5,680        396              1:21
      2019  ~6,690        462              1:32

    About 143,000 HYSPLIT runs in total, about 33 GB of compressed tdump
    (about 190 GB uncompressed).
  - /scratch quota: 19 TiB and 1,000,000 files (246,000 used on 2026-11-23).
    This is why CONTROL and tdump files are created on node-local disk and packed
    into one tar.gz per task (62 files per year).
  - SLURM on Fir: MaxArraySize = 10000.
  - Start points outside the usable NAM grid make the whole HYSPLIT run fail;
    they are excluded by Flag_NAM_domain.R (step 2b). If HYSPLIT ever reports
    "sources reduced", the run is listed in the run log and the converter
    matches the trajectories to their start points by coordinates.
    Trajectories that leave the grid during the run stop and give
    "off spatial domain" warnings (normal; complete = FALSE in GeoParquet).
  - Scratch files are purged when not used for a while: copy the results you
    keep to /project or nearline.
